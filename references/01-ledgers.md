# 01 · 三张台账

台账是这套方法的地基。没有台账，剩下的所有规则都会退化成"看着差不多就行"。

**一句话原理**：提示词是一份合同，台账是条款清单。跳过的条款不会消失，它会变成画面里说不清的"差一点"。

---

## 为什么是三张，不是一张

因为它们回答三个**不同**的问题，混在一张表里必然漏：

| 表 | 回答的问题 | 漏了会怎样 |
|---|---|---|
| **S** 需求 | 用户要了**什么**？ | 数值被改、文案被改、禁令被违反——而没人发现 |
| **X** 变形 | 什么东西**变成**了什么？ | 用交叉淡化/叠加/整帧缩放假装变形，观众感觉"不对但说不出" |
| **E** 元素 | 画面里**每一个**被画的东西设计过吗？ | 交 helper 的默认方盒子，全片像模板 |

---

## S 表：需求台账

### 收什么

提示词里**每一个可以变成数值或字符串的东西**：

- 时长、帧率、画幅、尺寸
- 每一个颜色（含 hex）
- 字体族、字重、字号、字距
- 每一句文案（逐字）
- 计数（"三个""五种"）
- 角度、位置、距离
- 时间点、缓动
- **禁令**（"不要渐变""不要出现人脸"）
- 循环 / 结尾要求
- 角色设定
- 分镜节拍

### 格式

```markdown
| id | 原文引用 | 落地位置 |
|---|---|---|
| S01 | "15 秒" | FILM.duration |
| S02 | "深墨绿 #1B3A2F" | COLOR.bg |
| S03 | "标题『静水流深』" | COPY.title |
| S04 | "不要出现任何渐变" | 禁用项 |
```

### 三条纪律

1. **原文引用，不是转述。** 台账里写用户的原话片段，不写你的理解。这样后续对账时能直接比对。
2. **不许自己补。** 提示词没写的，进 Stage 1 的补白表，并且**单独标记**（`S##*`），不能混在原文条目里。
3. **`FILM` 必须从 S 表来。** 这是最容易漏的一条：starter 模板里写着 `duration: 10`，弱模型经常忘了改，于是 15 秒的需求交出一个 10 秒的片子。**starter 的占位值不许活下来。**

### 截断处理

提示词被截断时（用户粘贴不全、模型输出被截），**不要停下来问**。按最后一节的语气密度补全，编号带星号，台账里注明：

```markdown
| S27* | （推测补全）"收在字标上，停 1 秒" | 结尾 hold |
```

星号 = 这是我猜的，不是用户说的。评审时优先核对星号条目。

## X 表：变形台账

### 收什么

提示词里**每一个"变成"类动词**：

> 变成、化为、汇成、长成、塌成、展开为、凝成、散作、转成、收成、撑开成

每出现一次，一行。

### 格式

```markdown
| id | 源 | 目标 | 机制 | 起-止(s) | 守恒什么 |
|---|---|---|---|---|---|
| X01 | 散落的词 | 一个计时器 | morphPts 同点数 | 3.2–4.6 | 词的数量 |
| X02 | 计时器 | 字标 | chain 共享槽位 | 8.0–9.4 | 圆心位置 |
| X03 | 五条柱 | 一条线 | converge 多对一 | 11.0–12.2 | 总长度 |
```

### "机制"这一列是重点

必须写清**物理上怎么变的**：

- `morphPts` 同点数逐点插值
- `chain()` 多段变形
- `converge()` 多对一合并
- `Reveal` 遮罩擦除
- `MaterialLayer` ×2 做材质改变
- 共享形状匹配

**不许写"淡入淡出""交叉淡化""缩放"**——那不是变形，那是逃避变形。

### "守恒什么"这一列

变形过程中什么数量/位置/身份必须不变？

- 词变成计时器：词的数量守恒（5 个词 → 5 个刻度）
- 柱变成线：总长度守恒
- 陶罐变成花瓶：圈足位置守恒

**守恒项写不出来的变形，说明你还没想清楚它怎么变。**

### 硬规则

- **没有 X 行的变形不许出现在片子里。**
- 说"变成柱状图"就得**收在柱子上**，不能停在半路。
- 源必须在目标成形时消失，目标必须完全到位。
- 部件在源的位置出生，然后 travel 过去。
- 合并/拆分要守恒数量。

## E 表：元素台账

### 收什么

**每一个被画出来的东西**——包括你以为不需要设计的东西（背景、分割线、光标、装饰点）。

### 格式

```markdown
| id | 元素 | playbook | 3+ 结构特征 | 尺寸/坐标 | 怎么动 |
|---|---|---|---|---|---|
| E01 | 陶罐 | Object | 收口颈、鼓腹、圈足、单侧暗部 | 420×560 @ (300,760) | 落地 settle |
| E02 | 标题字 | Type | Inter 800 / 96px / 字距 -0.02em | 单行 1400 宽 | 逐字 EASE.out 错开 0.04s |
| E03 | 背景墙 | Environment | 上浅下深、一道水平接缝、右侧光源 | 全幅 | 静止（环境生机不停但镜头不动） |
```

### "3+ 结构特征"是硬门槛

少于 3 个真实结构特征的物体，画出来一定是**符号**而不是**实物**：

- ❌ "一个杯子" → 画成方块加一个把手 = 符号
- ✅ "一个杯子：收口、单侧把手、杯底一圈反光、杯口椭圆透视" = 实物

**这是弱模型最常犯的错**：它把"杯子"这个词直接翻译成一个几何图形，而不是先想这个杯子长什么样。

### 角色的额外要求

角色必须额外提供两样：

**1. character sheet** —— 一帧里画出每个角色的**每个命名姿势**，并且**每个姿势都持有该持的道具**。

```
| 角色 | 姿势 | 道具 | 备注 |
|---|---|---|---|
| 阿岚 | idle | 无 | 基准 |
| 阿岚 | hold-lantern | 提灯（左手 grip） | 手必须贴灯柄 |
| 阿岚 | walk | 无 | walk() 驱动 |
```

**2. `Body` 设计表**：

```ts
const ALAN: Body = {
  torso: [64, 150], head: 52,
  color: { body: '#2F4A3E', head: '#E8D9C0', limb: '#2F4A3E', shoe: '#1A1A1A' },
  face: { eyes: 'dot', mouth: 'line' },
  parts: { hair: 'short-bob', scarf: '#C4553B' },
};
```

必须明确：剪影、比例、颜色、脸、标记。**不填就是火柴人。**

### 每场一张图层表

从后到前：

```
第 1 场 图层（后→前）：
  sky / far-hills / mid-trees / ground / 陶罐(E01) / 前景草叶
```

这张表直接决定代码里的 JSX 顺序，也决定"天气是否穿过实体""玻璃后的东西是否染色"。

## 回写源码

台账 id 必须出现在源码里，否则台账是废纸。

```ts
// spec.ts
export const FILM = { duration: 15, fps: 60, width: 1920, height: 1080 }; // S01
export const COLOR = { bg: '#1B3A2F', ink: '#F4F1EA', accent: '#C4553B' }; // S02 S05 S06
```

```tsx
// film.tsx
const Pot = (p: number) => (/* E01: 收口颈/鼓腹/圈足/单侧暗部 */ ...);
```

```tsx
// Scene02.tsx
// S31 X02 — 计时器 → 字标，8.0–9.4s
```

**没有 id 的常量就是没记账的常量。** `verify/spec.mjs` 会扫出来。

---

## 对账

写完代码后，跑：

```bash
node verify/spec.mjs --ledger LEDGER.md --src src/
```

它会告诉你：

- 哪些 S/X/E 条目在源码里**找不到 id**
- 哪些源码常量**没有 id**
- 有没有 **starter 占位符**残留（`TITLE` / `SUBTITLE` / `duration: 10`）
- 有没有**禁用项**（`linear-gradient` / `filter: blur` 做 glow / emoji）

覆盖率 < 100% 不是"差不多"，是**有条款没履行**。

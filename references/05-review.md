# 05 · 验收与复审

**这一篇是这套方法与所有同类项目的分界线。**

目标仓库用「五个模型评委打分」验收。问题是：**模型给自己打分，天然有确认偏差**——它会把自己刚写的东西看成"符合规格"，因为它就是这么想的。

所以这里把验收拆成两层：

| 层 | 谁做 | 判据 | 可反驳？ |
|---|---|---|---|
| **代码门禁** | 脚本 | 数字（覆盖率、SSIM、方差） | **不可**——数字就是数字 |
| **视觉复审** | 干净上下文的另一个 agent | 清单逐条 | 可，但要给时间戳证据 |

**代码门禁先跑，不过就是不过。** 不要用"我觉得还行"覆盖数字。

---

## 第一层：代码门禁

### `verify/spec.mjs`

```bash
node verify/spec.mjs --ledger LEDGER.md --src src/
```

查四件事：

| 检查 | 判据 | 不过怎么办 |
|---|---|---|
| 台账覆盖率 | 每条 S/X/E 都能在源码里找到 id | 补回写，或删掉没实现的条目并说明 |
| 未记账常量 | 源码里的 `const` / `export` 没有 id | 加 id 回写 |
| starter 占位符 | `TITLE` / `SUBTITLE` / `duration: 10` / `TODO` | 删掉，用真值 |
| 禁用项 | `linear-gradient`（无动机）/ `filter: blur` 做 glow / emoji / `Math.random` / `Date.now` | 换成合法实现 |

**覆盖率 < 100% 不是"差不多"，是有条款没履行。**

### `verify/film.mjs`

```bash
node verify/film.mjs --film out/film.mp4 --spec src/spec.ts
```

查六件事（全部基于 ffprobe + ffmpeg 实测）：

| 检查 | 判据 | 阈值来源 |
|---|---|---|
| 格式对 spec | width / height / fps / duration 与 `spec.ts` 一致 | 直接比对 |
| 首帧无闪色 | 第 0 帧与第 1 帧的平均色差 `dd ≤ 6` | 实测经验值 |
| 循环接缝 | 若 `loop: true`，末帧 vs 首帧 SSIM ≥ 0.97 | 实测经验值 |
| 运动曲线无尖峰 | 相邻帧差序列里，`v[i] > 4 × median && v[i] > 1` 的次数为 0 | 实测经验值 |
| 中段无死区 | 序列里 `v[i] < 0.005` 的连续段不超过 0.5s | 实测经验值 |
| 音频非静音 | `FILM.sound` 为 true 时，音轨 RMS 不得全零 | 直接测 |

**信 stills 胜过信代码。** 代码说"我动了"，抽帧看可能是静止的。

## 第二层：视觉复审

### 谁来做

起一个**干净上下文的 subagent**。**只给它**：

- 成片 MP4（或抽帧拼图）
- 关键帧（开场 / 关键解释 / 结尾，最多三张）
- `LEDGER.md`
- 原始提示词

**不给**：制作过程、你的自我评价、你的设计意图说明。

> 制作者对自己的产出有确认偏差。首检永远不能交给用户，也不能交给自己。

### 五个维度

每维 1–10 分，**每条问题必须带时间戳**。

| # | 维度 | 查什么 |
|---|---|---|
| 1 | **SPEC** | 每行 S/X/E 是否以精确值实现；列出缺失或被改的 id。**这一分是总分上限。** |
| 2 | **CONTINUITY** | 每个 X 行是真变形且到达目标；部件在源处出生；身份与槽位跨场跨材质延续；物理与景深正确 |
| 3 | **RHYTHM & SOUND** | 事件落在拍上；缓动符合契约；能量均匀无计划外尖峰与空秒；每个 hit 都有声音；循环接缝干净 |
| 4 | **DESIGN** | 主帧符合布局；占据与留白符合契约；每个元素过其 playbook 检查；放大看字/脸/手/道具/数据标签；外观是为本片设计的，不是 helper 默认或某示例的 |
| 5 | **CRAFT** | 质感与光按元素；确定性且守工程契约；**禁用清单**（见下） |

### 处理

**低于 8 分的维度，问题逐条修，最糟优先，最多三轮。**

三轮还不行，如实报告限制——不要假装修好了。

## 禁用清单

以下出现即扣分（`spec.mjs` 会抓源码，复审会抓画面）：

| 禁用 | 例外 |
|---|---|
| 未被要求的渐变 | 有光源动机的光形 |
| glow / bloom / 霓虹光晕 / 镜头光斑 | 有光源动机的光形 |
| 通用淡入（每个元素都 fade in） | 无 |
| 被禁处的回弹 | 提示词要求回弹 |
| 粒子爆发 | 提示词要求 |
| 镜头抖动 | 手持感是设计意图 |
| RGB 分离 | 提示词要求 |
| 「卡片上居中标题」版式 | 无 |
| stock 图标 / emoji | 无 |
| 占位文案（Lorem / 待填 / TBD） | 无 |
| 任何像模板的东西 | 无 |

**「有动机的光画成形」是允许的**——锥形光束、亮窗、反射。区别在于：光**有形状**，不是一团模糊。

## 有界复核

首渲后**只做一次**复核：

1. 查时钟 / 尺寸
2. 把字幕对回不变量（文案逐字比对 S 表）
3. 最多看**三帧**代表帧（开场 / 关键解释 / 结尾）
4. 看循环接缝（如果循环）

发现具体缺陷 → **最多一次定向修复并重渲**，只复查受影响的事实/帧。

仍不对就**如实报告限制**。

---

## 不许做的事

- ❌ 给美学编一个数字分数（"美学 87 分"——这个数字从哪来？）
- ❌ 派验收 agent 之后又自己改（复审的意义是独立）
- ❌ 加独立的流水线阶段（七阶段够了）
- ❌ 无休止打磨循环（三轮上限）
- ❌ 把未渲染的视频说成完成

---

## 报告格式

```
## 门禁
spec.mjs: PASS / FAIL（覆盖率 47/47，占位符 0，禁用项 0）
film.mjs: PASS / FAIL（格式✓ 首帧✓ 接缝✓ 尖峰✓ 死区✓ 音频✓）

## 复审（独立 agent）
SPEC 9 / CONTINUITY 8 / RHYTHM 7 / DESIGN 8 / CRAFT 9
问题：
- 07.2s RHYTHM：第三个 hit 没有音效
- 12.8s DESIGN：数据标签压住柱顶

## 修复
已修 07.2s（补 tick 音效）、12.8s（标签上移 24px），重渲后复查两帧通过。

## 我仍不确定的
- 14.0–14.6s 的收尾停顿是否太长（用户没给具体值，按补白表取了 0.6s）
```

**「我仍不确定的」这一段必须写。** 它是唯一能让用户知道该看哪里的东西。

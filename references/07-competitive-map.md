# 07 · 同类项目地图

这一篇回答一个问题：**为什么还要做 motion-ledger？**

答案是：现有项目各自解决了一部分，但**没有一个是"给弱模型用的验收机器"**。

## 三个空白，正好是本项目的三个设计点

### 空白 1：验收靠模型自评

目标仓库的五评委、open-design 的美学评审，**都是让模型给自己打分**。

模型的确认偏差是结构性的：它按自己的理解实现，再按同一个理解验收，永远自洽。

**huashu 是唯一做了真门禁的**（`film_gate.py`：整片几乎没有镜头内快动作就红灯），但它绑定自家引擎，不可迁移。

→ **本项目的 `verify/*.mjs` 是纯 Node、零依赖、可迁移的代码门禁。** 这是原创部分。

### 空白 2：台账写在文档里，但没人核对

目标仓库要求标 `// S07`，但没有脚本检查。标不标全靠自觉。

→ **`verify/spec.mjs` 做覆盖率对账**：台账条目找不到 id 就报，源码常量没有 id 也报。

### 空白 3：「模型平价」这条赛道没人接力

GitHub 全站搜索，做「让弱模型产出接近强模型」的只有目标仓库和它的一个空白 fork（0 star）。

其余项目都假设**执行模型已经够强**，所以它们把力气花在"怎么做出好视频"，而不是"怎么防止模型偷懒"。

→ **本项目的每条规则都针对一个具体的偷懒行为**：
- 台账 → 防止改数值
- X 表 → 防止用淡入淡出假装变形
- 3+ 结构特征 → 防止符号代替实物
- 门禁 → 防止自我感觉良好

## 参考但未采用

| 项目 | 为什么不用 |
|---|---|
| `OpenMontage` | AGPL-3.0 传染，商用/闭源集成受限 |
| `hyperframes` | 是渲染后端，与本项目不冲突（本项目不管后端） |
| `what-if-animation` | 单题材（What If 火柴人），公式不可迁移 |
| `xilo-opus-video` 的「三方案」 | 与 open-design 的「不要卡住只想让你做片子的用户」冲突；本项目选后者 |
| `video-shotcraft` 的镜头卡 | 124 张卡是资产不是方法；本项目只吸收「独立终检」与「确定性渲染」两条纪律 |

## Remotion 许可（必须告知用户）

- **个人使用免费。**
- **公司 ≤ 3 人免费。**
- **更大的公司需购买 Remotion 公司许可。**

这条在三个独立项目里被重复确认（目标仓库、`what-if-animation`、`video-shotcraft`）。

如果用户是公司场景，**在开始制作前就要说明**，不要做完才提。

# 06 · 声音

**默认有声音。** 用户没说要静音，就有声音。

弱模型最常见的偷懒：全片静音，或者拿噪声当音乐。两个都会被门禁抓。

---

## 三条决定，分开做

| 决定 | 内容 | 谁定 |
|---|---|---|
| **voice** | 有没有旁白 / 配音 | 提示词有台词才有 |
| **music** | 有没有音乐床 | 默认有 |
| **effects** | 有没有音效 | 每个视觉打击都要有 |

**「不要旁白」只禁语音，不禁音乐音效。**
**显式静音请求优先**（"要静音""不要声音"）→ 全片静音，且 `FILM.sound = false`。

---

## 音乐规格

### 结构

```json
{
  "duration": 15,
  "bpm": 120,
  "loop": true,
  "palette": ["pluck", "pad", "tick"],
  "bed": [
    { "at": 0, "dur": 15, "inst": "pad", "notes": [220, 277.18, 329.63] }
  ],
  "patterns": [
    { "inst": "pluck", "every": 0.5, "notes": [440, 554.37, 659.25], "from": 0, "to": 15 }
  ],
  "events": [
    { "at": 1.4, "inst": "tick", "gain": 0.5 },
    { "at": 3.2, "inst": "whoosh", "gain": 0.6 }
  ]
}
```

### 规则

- **音乐必须来自有音高的乐器**（pluck / bell / pad / kick 有音高）。
- **噪声只做点缀，且 < 1s**（whoosh / scratch）。
- 环境主导的场用 `ambience` 床（rain / wind / room），不要拿音乐压环境。
- **既无音乐也无 ambience 时，脚本拒绝出谱**——这是硬门禁，不是建议。

### 乐器

```
pluck / bell / pad        有音高，做床与乐句
ambience(rain|wind|room)  环境床
tick / kick / clap / hat  节奏
whoosh / drop / knock / scratch / boom  点缀（< 1s）
```

## 音效对齐

**每个视觉打击都要有声音，且落在同一个时间点。**

音效时间**从时间线事件表派生**，不要手写第二份时间表——那样一定会漂。

```
事件表 t=1.40s: E02 标题逐字入场
  → cues.json events: { at: 1.40, inst: "tick" }
```

对齐误差容忍 **≤ 3 帧**（60fps 下 50ms）。超了就是"音画不同步"，观众能感觉到。

---

## 循环

`loop: true` 时：

1. 音乐尾部的余韵**折进开头**（不要硬切）。
2. 音频总长必须**等于**视频总长。
3. 末帧音频电平与首帧接近（不要结尾突然静音）。

---

## 响度

母版目标 **-14 LUFS**（流媒体标准）。

```bash
ffmpeg -i raw.wav -af loudnorm=I=-14:TP=-1.5:LRA=11 -ar 48000 out/score.wav
```

- `I=-14`：整体响度
- `TP=-1.5`：真峰值上限，防削波
- `LRA=11`：响度范围

---

## 常见失败

| 失败 | 症状 | 修法 |
|---|---|---|
| 默认静音 | 全片无声 | 加 pad 床 + 事件音效 |
| 拿噪声当音乐 | 嘶嘶声铺满 | 换成有音高的乐器 |
| 打击不对拍 | 音效比画面晚 | 从事件表派生，不手写 |
| 音效太响 | 盖过音乐 | `gain` 降到 0.3–0.6 |
| 结尾硬切 | 循环接缝有咔哒 | 尾部折进开头 + 淡出 |
| 响度太低 | 手机听不见 | loudnorm 到 -14 LUFS |

## 何时用真配乐

代码合成的音色是**简单**的。如果用户明确要求音乐质量：

> 如实告知：本方法产出的是代码合成配乐，音色简单。要求高的建议后期替换为真实配乐，时间线不变（`cues.json` 的 `events` 就是替换时的对齐表）。

不要假装合成配乐能达到商业音乐水准。

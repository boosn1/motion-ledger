# 09 · 能做什么，不能做什么

这份清单是按**真实可交付**写的，不是按「理论上可以」。每一类都标了它在什么条件下能做好、什么条件下会翻车——后者比前者更重要。

---

## 能做的（按把握度排序）

### 一句话总表

| 类型 | 把握 | 实测相似度 | 典型时长 | 首次耗时 | 改一版 |
|---|---|---|---|---|---|
| 品牌/产品动效片 | 最大 | — | 15–60s | 2–4 小时 | 20–40 分钟 |
| 数据动画 / 图表变形 | 很大 | **0.85–0.96** | 15–40s | 3–6 小时 | 30–60 分钟 |
| 动态文字 / Logo 演绎 | 很大 | **0.79–0.94** | 5–30s | 1–2 小时 | 10–20 分钟 |
| 讲解片 / Explainer | 中上 | — | 60–120s | 1–2 天 | 1–2 小时 |
| UI / 产品演示 | 中 | — | 15–40s | 2–5 小时 | 30–60 分钟 |
| 风格化艺术动画 | 中 | **0.68–0.89** | 10–40s | 2–6 小时 | 30–90 分钟 |
| 角色短片 | **最低** | **0.40–0.49** | 不确定 | 不确定 | 不确定 |

**相似度是什么**：原项目把同一段提示词分别交给强模型（Opus）和弱模型（DeepSeek + 本 skill）各做一支片，再在同一时间点取帧、转灰度、算 SSIM（0–1）。数字越高，说明「弱模型 + 台账流程」离「强模型直接做」越近。这不是美学评分，是**可复现的结构相似度**——它能说明「流程有没有把该做的动作做出来」，不能说明「好不好看」。

**为什么品牌片没有数字**：原项目没测这一类。它在表里排第一是因为机制上最稳（元素来路去处明确、构图可 px 级定死、无需生成），不是因为有实测分。**没有数字的地方就该说没有数字**，编一个区间比空着更糟。

**读这张表的正确方式**：从下往上看。角色短片 0.40–0.49 意味着「流程能跑通、能出片、能过门禁，但画面会和强模型做出来的东西明显不一样」。数据动画 0.85–0.96 意味着「几乎只剩细节差别」。**这就是把握度的来源——不是感觉，是差多少。**

---

### 1. 品牌/产品动效片，15–60 秒 — 把握最大

五个方块依次长出、聚成环、环拉直变成字标——这类「元素有明确来路和去处」的片子，是这套流程最擅长的。

**为什么稳**：每个元素都是代码里的函数，形状、位置、颜色全在 `spec.ts` 里写死。没有「生成」这一步，所以没有可漂移的东西。同一份代码渲两遍，逐帧完全一致。

**适合**：产品发布短片、品牌片头、活动开场、App 功能预告。
**不适合**：需要真人质感、需要实拍素材的。

实测：`templates/remotion-starter/` 就是这一类，15 秒、1920×1080、带配乐，门禁全绿。

---

### 2. 数据动画 / 图表变形 — 把握很大

数字滚动、柱状图生长、折线画出、饼图拆成环。数据动画的难点从来不是画面，是**数字对不对**。台账里每个数字都是原文引用的，代码只读台账，不自己编。

**为什么稳**：数值可追溯。台账 S 表里写 `S07 复利 6.5%`，代码里就必须是 `// S07` 那个常量。门禁会查覆盖率——台账写了但代码没兑现，直接红。

**适合**：财报解读、增长数据、对比分析、科普讲解。
**要注意**：图表类型别混着用。一场一张图，先说轴和单位，再说数据。

---

### 3. 动态文字 / Logo 演绎 — 把握很大

标题逐字入场、字重变化、字距呼吸、整句作为一个单元移动、最后收在定版。

**为什么稳**：文字是矢量，没有模糊边界。CJK 竖排、字距、按宽度自适应都能算准。
**适合**：片头字标、章节标题、金句卡、Slogan 演绎。
**已知限制**：中文字体要本地装或走 `@remotion/google-fonts`。没装 Noto Sans SC 会 fallback 到系统字体，字宽就变了。

---

### 4. 讲解片 / Explainer — 把握中等偏上

有旁白时间轴时，按词级时间排镜头；没旁白时按台账的节拍表排。

**中文旁白的一个现实约束**：词级时间戳不是免费的。实测 `edge-tts`（免费档最好的一档），`--write-subtitles` 对中文只给**整句**时间（`00:00:00,050 --> 00:00:02,432 光速每秒三十万公里。`），`WordBoundary` 事件对中文返回 0 条——英文有词边界，中文没有。所以「念到哪个词画面跳哪个数」这种效果，中文必须用付费方案（ElevenLabs 中文支持词级、火山/阿里云有词级时间戳 API）。免费档只能做到**句级对齐**：一句旁白对齐一个镜头或一个数据揭示，不能逐词卡。

配音本身不在本 skill 范围内（见下方「不能做的」）。真要接，正确姿势是：人声先出、按句级时间回填 `T0`–`Tn` 关键时刻，再让画面去贴合它——而不是先做完画面再往上贴声音。

**能做**：几何图示、流程动画、概念拆解、空间隐喻（因果模型要保住）。
**不太行**：需要大量手绘插画风格的讲解片。这类要的是绘画能力，不是排版能力——纯代码画出来会像 PPT。这是同类项目的共识（`what-if-animation` 的 README 明说「painted/textured styles aren't realistic in pure code; they need an image model」）。

---

### 5. UI / 产品功能演示 — 把握中等

**能做好的前提**：有真实截图，或者忠实重建的界面（矩形清晰、比例真实、层级真实）。
**做法**：截图作为底图，用遮罩和光标动效指示「点了哪里、发生了什么」，然后放大到变化区域。
**会翻车**：手搓一个假界面。小字不可读、间距不对、控件比例失真——一眼就看出来是假的。这种情况应该回去要真截图，而不是把假界面做得更精致。

---

### 6. 风格化艺术动画 / showreel — 把握中等

7 种材质世界逻辑（editorial ink / precise instrument / folded paper / tactile collage / vector geometry / painterly field / riso halftone），每种都有自己的建法与失败模式。

**能做**：纸质、墨感、半调、排线、几何构成、拼贴。
**不太行**：真正的厚涂、油画笔触、水彩晕染。代码能模拟纹理，但模拟不出「笔触是有情绪的」。要这个效果，得接图像模型生成素材，再把素材当贴图用。

---

### 7. 角色短片 — 把握最低，先说清楚

README 里那组数据最能说明问题：目标仓库自测「雨中站台」这类角色故事片，与 Opus 版相似度只有 **0.40–0.49**，而数据动画能到 0.85–0.96。

**为什么弱**：角色要的是表演——重心、预备动作、跟随、情绪。代码里的 `rig()` 能保证「脚在地上、手在道具上、镜头间形象不漂移」，但保证不了「这一下转身有没有戏」。

**能做到的**：火柴人级别的走位、简单的姿势切换、剪影式的叙事（`what-if-animation` 证明这条路可行，它的角色是代码里的 rig，同一个函数画每一镜，所以不会漂移）。
**做不到的**：有表演质感的角色动画。这个要动画师，或者要动捕。

## 不能做的（明确划出去）

| 不能做 | 为什么 | 该用什么 |
|---|---|---|
| 真人拍摄 / 实拍素材 | 这是渲染器，不是摄影机 | 摄像机 |
| 剪辑现成素材、加字幕、转场 | 这是生成器，不是剪辑器 | Concat / 剪映 / DaVinci |
| 写实画面生成（人物、风景、产品照） | 代码画不出照片 | 图像模型（Flux/SD/Midjourney） |
| 语音合成 / 配音 | 配乐是合成音，语音不在范围内 | ElevenLabs / edge-tts / 火山 |
| 长视频（>2 分钟）的完整叙事 | 代码量会爆炸，且改一处要重渲全片 | 分段做，再拼接 |
| 需要「像人做的」手绘感 | 代码的线条太干净 | 图像模型 + 手绘 |

## 一条判断规则

拿到需求，先问一个问题：**这个画面的难点是「精确」还是「质感」？**

- **精确**（数值要对、形状要准、时间要卡拍、跨镜头要一致）→ 这套流程有优势，代码比人手稳。
- **质感**（要像画的、要像拍的、要有笔触、要有人味）→ 这套流程会输，该接图像模型或找设计师。

两类混在一起时，正确做法是**分开做**：质感的用图像模型出素材，精确的用代码排布。不要试图用代码模拟质感，也不要试图用图像模型保证精确。

## 时间与成本的实际估计

| 片子类型 | 首次做出 | 改一版 | 主要时间花在 |
|---|---|---|---|
| 15s 品牌片（5 元素） | 2–4 小时 | 20–40 分钟 | 台账 + 关键构图定版 |
| 30s 数据动画（3 图表） | 3–6 小时 | 30–60 分钟 | 数据核对 + 图表变形 |
| 15s 动态文字 | 1–2 小时 | 10–20 分钟 | 字体与字距调校 |
| 60s 讲解片（6 场） | 1–2 天 | 1–2 小时 | 时间线 + 场景衔接 |
| 30s 角色短片 | 不确定 | 不确定 | 表演，而这是代码最弱的地方 |

「改一版」比「首次做」快得多，因为台账还在——改的是数值，不是重新设计。这是台账最大的实际价值：**它让修改变成改参数，而不是重做**。

## 交付物是什么

一次完整的交付会留下这些东西：

```
my-film/
  LEDGER.md              三张台账 + 时间线 + 计划内峰值/静止声明
  src/spec.ts            所有设计常量（每个都标了台账 id）
  src/scenes/            每场一个文件
  out/film.mp4           成片
  out/check/             门禁抽帧、拼图、运动曲线、音频波形
  final.mp4              （可选）Concat 加完字幕的交付版
```

`LEDGER.md` 是最重要的那个——三个月后要改，看的是它，不是代码。
